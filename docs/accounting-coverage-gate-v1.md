# ACCOUNTING_COVERAGE_GATE_V1

`ACCOUNTING_COVERAGE_GATE_V1` is a read-only release gate, not a new accounting model or matcher. Its central invariant is:

> Internal consistency is not coverage completeness. READY financial evidence must never disappear silently.

## Primary Outcome

Each normalized receipt is assigned exactly one primary outcome:

`ACCOUNTED_PURCHASE`, `PREPAYMENT_COMPONENT`, `FULFILLMENT_COMPONENT`, `RETURN`, `REFUND`, `ADVANCE`, `CREDIT_OR_LIABILITY`, `AMBIGUOUS`, `UNSUPPORTED`, `BLOCKED`, `OTHER_EXPLICIT`, or `UNEXPLAINED`.

`UNEXPLAINED` is a hard failure for any READY receipt. Exposure is reported as `fiscal_coverage_exposure`, not spend, expense, acquisition, or bank outflow.

## Commands

```text
receipt-collector coverage summary [--out report.json]
receipt-collector coverage period --from <ISO> --to <ISO>
receipt-collector coverage receipt <receipt-id>
receipt-collector coverage compare baseline.json candidate.json [--allowlist allowlist.json]
```

Exit code `0` means PASS. Exit code `2` means a coverage gate failure. Output is deterministic JSON and contains per-receipt outcomes, operation/payment-stage matrix, exposure, reason/rule provenance, and layer diagnostics.

## Hard Fail Rules

- Any READY receipt routes to `UNEXPLAINED`.
- A previously `ACCOUNTED_PURCHASE` receipt becomes `UNEXPLAINED`.
- A previously `ACCOUNTED_PURCHASE` receipt becomes `UNSUPPORTED`, `AMBIGUOUS`, or `BLOCKED` without an explicit reviewed allowlist entry.
- A previously covered operation/payment-stage class disappears.
- Baseline and candidate reports advertise different `sourceStateKey` values.
- Any layer reports an unexplained routing gap.

Allowlist entries must explicitly name the receipt, old outcome, new outcome, reason, and model version. They are never generated by the comparison command.

## Layer Boundaries

The report separates source-to-normalization, normalization-to-graph, graph-to-ledger, ledger-to-certification, and certification-to-analytics diagnostics. It does not require every fiscal receipt to become an acquisition; it requires every READY receipt to have an explainable destination.

## Release Contract

Accounting-changing work must run the gate on fixtures and on a disposable production clone before a READY FOR DEPLOYMENT verdict. Production is not changed by this implementation.

## Reproducible Clone Check

The read-only clone runner is `scripts/run-accounting-coverage-gate.mjs`. It writes deterministic reports when `COVERAGE_OUTPUT_DIR` is set and exits non-zero unless the current all-time and August reports pass, the same-snapshot comparison passes, and the historical standalone-omission simulation fails as designed. The checked clone artifacts are under `artifacts/accounting-coverage-gate-v1/`.

The runner uses only normalized facts, graph evidence, ledger/certification links, and the curated analytics view. It does not call FNS, persist graph objects, rebuild ledger/certification, or alter the database.
